# 领域约定：多渠道撤回与替换

产品配方、商标、包装、营销素材、代言范围和法规条款按有效期共同核对。
本模块解决的具体问题是：**一封下架邮件不能证明市场上已经停止传播**。
当素材已被直营网店、经销商短视频账号、线下屏幕和明星团队多次转载时，系统必须把
处置动作落实到每一个可核验的展示位置，并在处置结束后持续发现已撤回内容的再次传播。

外部主体一律使用不含真实身份信息的引用编号，时间采用带偏移量的 ISO 8601 字符串
（存储统一规范为 UTC 毫秒精度 `Z`），附件只记录受控引用或 `sha256` 摘要。
业务事件需要携带来源与序列号（`source_system` + `source_sequence`），保留来源系统对事实的责任边界。

## 核心对象与传播清单

- **incident（风险事件）**：由最初风险通知产生，同一来源+序列号不重复建单。
- **asset（素材）**：`original` 原始件、`derivative` 裁剪/改字派生件（记录父素材与变换说明）、
  `replacement` 替代素材。内容以 `sha256` 指纹标识，监测靠指纹识别改头换面的复发。
- **placement（展示位置）**：一个商品页、一条视频、一块屏幕的一个播放位。
  `locator` 必须可核验（URL、屏幕编号、页面路径），归属渠道负责人主体
  （品牌 / 经销商 / 代言团队）。
- **notice（处置通知）**：风险负责人圈定范围与期限后，系统按渠道负责人分组，
  发出带唯一编号 `N-<事件>-<序号>` 的通知，一封覆盖其名下多个点位。
- **evidence（结果凭证）**：平台回调（`platform_callback`）、人工截图摘要
  （`manual_screenshot`）、现场复核（`field_recheck`）、联系结果（`contact_record`）。

## 状态机

```
placement: identified → scoped → notified → resolved
                                  ↑            ↓ 监测再次发现
                                  └── recurred （事件重新激活，新一轮通知）
notice:    issued → completed（名下点位全部 resolved）
                   superseded（复发重发且名下无其他未闭环点位）
evidence:  pending_verification → verified / rejected
```

不可变规则：

1. **重复回调不能提前关闭任务**：平台回调以 `delivery_id` 幂等，重复投递原样返回首条凭证，
   不写入新状态、不推进任何点位。
2. **凭证必须核验**：提交方"声称完成"（含 `claimed_complete=true`）只是声明；
   风险负责人/法务核验通过，点位才 `resolved`。
3. **漏报不能当完成**：声称全部完成但缺少通知下部分点位的凭证时，凭证被拒并开
   `partial_replace` 升级。
4. **通知闭环以点位为准**：通知覆盖的每个点位都 `resolved` 后通知才 `completed`。

## 四类升级路径（相互独立）

| 类型 | 触发 |
| --- | --- |
| `unreachable` | 联系结果为无法联系（邮件退信、账号无响应），并累计 `contact_attempts` |
| `refused` | 渠道方明确拒绝下架 |
| `recurrence` | 已 `resolved` 点位（或已全部撤回的素材在新位置）再次出现；点位回到 `recurred`，事件重新激活 |
| `partial_replace` | 同一通知下仅部分页面闭环，或声称全部完成但漏报点位，或替代素材缺放行 |

升级有 1→2→3 三个级别；处置复发时可重发新一轮通知（新唯一编号、新期限）。
若旧通知名下还有其他未闭环点位，旧通知不取消，仅把复发点位移交新通知。

## 替代素材的独立放行

替代素材**必须**由合规审核（`compliance` 角色）以独立审核批次 `review_batch_ref`
作出放行决定（`release_approvals`），并在核验时点处于有效窗口
（`valid_from <= now < valid_to`）。旧素材撤回不会自动产生放行；放行过期或缺失时，
替换核验被拒，点位保持开放并进入 `partial_replace` 升级。

## 数据范围（RBAC）

- `dealer`：只能看到和处置本主体（`owner_org_type/owner_org_id`）名下点位与通知。
- `talent`（代言团队）：仅本主体点位，且响应中**剥离配方版本号与消费者材料**
  （`formula_revision`、`consumer_material`、`transform_note`、凭证摘要/附件）；
  内容指纹 `sha256` 仍可见，因为处置方需要核对目标。
- `executive`：不直接处置，通过覆盖率/逾期仪表盘实时掌握全局。
- 平台回调与联系结果只能由品牌侧登记；经销商/代言团队可就自己点位提交截图与复核材料。

## 监测与闭环

- `POST /v1/observations`：监测/举报/平台回流按 `sha256` 匹配素材。命中已撤回内容即开
  `recurrence` 升级；处置中素材在新位置出现则作为新点位纳入清单待圈定。
- `POST /v1/scan/overdue`：标记过期限未闭环点位（幂等），并派生逾期通知清单。
- 事件结束（`close`）要求无未闭环点位且无 open 升级；之后进入 `monitoring` 阶段，
  监测不停止，发现复发自动转回 `open`。
- `GET /v1/incidents/{ref}/trace`：从最初风险通知（含来源系统与序列号）到每个点位
  实际下架/替换时间、每封通知、每份凭证与每次升级的完整追溯链。

## 时间与格式

时间输入接受任意带偏移量的 ISO 8601；系统落库前统一转为 UTC `...Z` 以保证字符串比较语义
（期限、放行窗口、逾期判定都依赖时间比较）。
